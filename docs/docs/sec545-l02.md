# SANS SEC545 Cloud Security Simulator Setup Guide (L02)

SEC545 students can follow these instructions to build the labs in their personal AWS accounts. Doing so allows students to complete the labs after access to the SANS provisioned accounts is expired.

- AWS free tier eligible accounts are expected to cost roughly $30 USD per day for the AWS resources (including the StudentVM). Make sure you tear down the environment when you are not using it.


To limit costs, please make sure to run the **Tear Down** script (`~/code/genaiapp/destroy_lab.sh`) when you are not using the lab environment.

!!! warning "YOUR Financial Responsibility"

    When running the Cloud Security Flight Simulator and performing the corresponding labs in your personal AWS / Azure environments, **YOU** are responsible for all costs.

!!! warning "OpenAI BASE URL"

    In class, SANS provided you with a litelLLM key. When you want to run labs in your personal AWS account, you will need to use your own OpenAI API key and OpenAI's direct API endpoint. 
    The OpenAI direct API endpoint (OPENAI_API_BASE in ~/.env file) is `https://api.openai.com/` instead of `https://sans.litellm-prod.ai`.


### Step by Step Instructions

1. Configure your AWS CLI with administrator credentials for your AWS Account.

    ```bash
    aws configure
    ```

- Create a new working directory and download both the Terraform template and the deployment wizard into it.

    ```bash
    mkdir ~/sec545
    cd ~/sec545
    ```

    Download both of the following files into the `~/sec545` directory:

    - [sec545-l02.tf](./assets/sec545-l02.tf) - the Terraform launch template
    - [wizard-sec545.sh](./assets/wizard-sec545.sh) - a wizard script that builds and destroys the lab for you

    Make the wizard script executable:

    ```bash
    chmod +x wizard-sec545.sh
    ```

- After the instructor or OnDemand SME shares the AMI with your personal AWS account, confirm it is visible by running:

```bash
aws ec2 describe-images \
--region us-east-2 \
--owners 469658012540 \
--filters Name=name,Values='*sec545*' Name=state,Values=available \
--query "sort_by(Images,&CreationDate)[].{AMI:ImageId,Name:Name,Created:CreationDate}" \
--output table
```

You should see at least one image.

- Run the wizard from the `~/sec545` directory to build the lab range. Do not run `terraform` commands directly.

```bash
cd ~/sec545
./wizard-sec545.sh
```

    The wizard will:

    1. Ask you to pick an AWS CLI profile (if you have more than one configured).
    2. Print the AWS account ID and IAM identity it is about to deploy into - **double check this is your personal account** before continuing.
    3. Show a menu; choose **1- Build range** to deploy the lab.
    4. List the SEC545 AMIs shared to your account (most recent first) so you can pick one.
    5. Run `terraform init` and `terraform apply` for you.

    !!! tip "Non-interactive usage"
        You can skip the menus, e.g. `./wizard-sec545.sh --deploy --ami-id ami-0123456789abcdef0 --yes`. Run `./wizard-sec545.sh --help` to see all available options.

- The deployment takes a few minutes to complete. Once it finishes, you will see the following:

    - The `environment_summary` output contains the information you need to connect to the StudentVM.

    - *SmartProxy Config* - The name of the SmartProxy configuration file created in the `~/sec545` directory.

    - *SSH + SOCKS Connect Command* - The command to connect to the StudentVM using SSH and the SOCKS proxy with the private key created in the `~/sec545` directory.

    ```plain
    Apply complete! Resources: 16 added, 0 changed, 0 destroyed.

    Outputs:

    environment_summary = <<EOT
    Latest AMI:  ami-06cb88e1e8c394247 - sans-sec545-l02.25.1.0
      Running AMI: ami-06cb88e1e8c394247
      Public IP:   3.15.0.118

      Local IP:          71.34.29.101
      Allow CIDR:        71.34.29.101/32

      Proxy Pass:        intensely_luckily_bursting_pelican
      SmartProxy Config: SmartProxy-enjoyed-crawdad.json

      SSH + SOCKS Connect Command

          ssh -i enjoyed-crawdad.pem -D 54640 student@3.15.0.118

    EOT
    ```

- Follow the course **Lab Setup Instructions** guide to install the StudentVM CA certificate, configure the SmartProxy extension, and connect to the StudentVM.

## AWS student IAM User

To deploy the lab infrastructure to AWS, you need to create a new `student` IAM user. The easiest way to set permissions is by attaching the **AdministratorAccess** policy. Our recommendation is to use a permission boundary on this IAM user to restrict access to services not used in the AWS labs. Then, create a new pair of access keys for authenticating the StudentVM to your account.

### Requirements

- Provided by you:
    - AWS personal account with administrator credentials

### Step by Step Instructions

1. Log into the [AWS Console](https://aws.amazon.com/){:target="_blank"} using your personal administrator account.

- See the [Creating an IAM user in your AWS account](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_users_create.html){:target="_blank"} documentation to create a new `student` user.

- See the [Adding permissions to a user (console)](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_users_change-permissions.html#users_change_permissions-add-console){:target="_blank"} documentation to attach the `AdministratorAccess` policy.

- See the [Managing access keys for IAM users](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_credentials_access-keys.html){:target="_blank"} documentation to create a new pair of access keys for the `student` user.

- Follow the **Lab 1.0 - AWS Cloud Account Setup** instructions in the electronic workbook to configure the StudentVM AWS Command Line Interface (CLI).


## Clean Up

- When you are finished with the labs, run the wizard's destroy option from the `~/sec545` directory. Do not run `terraform destroy` directly.

    ```bash
    cd ~/sec545
    ./wizard-sec545.sh
    ```

    Choose **2- Destroy range** from the menu (or run `./wizard-sec545.sh --destroy --yes` directly).

    The wizard automatically SSHes into the StudentVM and runs **~/code/genaiapp/destroy_lab.sh** for you, then runs `terraform destroy` to remove the StudentVM, the SmartProxy configuration file, and the other AWS resources from your account.

    !!! tip
        If the automatic SSH step fails (e.g. the VM is already unreachable), the wizard logs a warning and still proceeds with `terraform destroy`. You can also pass `--skip-remote-teardown` to skip that step entirely.
